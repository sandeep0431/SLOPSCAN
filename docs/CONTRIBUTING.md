# Contributing to SlopScan

Thank you for your interest in improving SlopScan!

SlopScan is dedicated to helping developers and designers craft disciplined, intentional user interfaces through evidence-first, objective inspection.

---

## Guiding Principles

Before contributing code, rules, or design changes, please internalize our core standards:

1. **Evidence > Score**:
   Every finding must be backed by measurable DOM/CSS properties, explicit selectors, and actionable advice. We never report subjective insults or opaque percentages.
2. **Local-First & Private**:
   No website content, DOM nodes, or computed styles may be transmitted off the user's machine. SlopScan operates entirely within the browser client.
3. **No "Generic AI SaaS" Aesthetic**:
   SlopScan's own interface must exemplify the craft it advocates: restrained border radii, disciplined typography, absence of decorative gradients or colored glows, and zero gimmickry.
4. **Accuracy Over Volume**:
   A scanner with 10 high-precision rules is infinitely better than one with 100 noisy, false-positive-heavy rules.

## Adding a New Rule

All new rules must follow this process:

### 1. Specification
Add the rule definition to `docs/RULES.md`:
- Rule ID (e.g. `R033`)
- Category (`surfaces`, `spacing`, `typography`, `icons`, `copy`, `components`, `layout`, `motion`)
- Detection heuristic
- Severity (`high`, `medium`, `low`)
- Default confidence (`high`, `medium`, `review`)
- Concrete recommendation

### 2. Implementation
Implement the rule inside `src/engine/rules/`:
```ts
export const R033_Rule: Rule = {
  id: 'R033',
  category: 'icons',
  title: 'Inconsistent Icon Alignment',
  run(context: ScanContext): Issue[] {
    // Traverse context.elements and return structured issues with exact evidence
  }
};
```

### 3. Test Cases
Add unit tests in `tests/rules/` covering:
- Positive detection case (the pattern is accurately flagged with correct evidence)
- Negative case (valid UI pattern that must NOT be flagged)
- Edge case (unusual DOM structure, SVG icons, text nodes)

## Development Setup

### Prerequisites
- Node.js (v18+)
- npm or pnpm

### Getting Started

```bash
# Clone the repository
git clone https://github.com/your-org/slopscan.git
cd slopscan

# Install dependencies
npm install

# Run dev build with hot reloading
npm run dev

# Run test suite
npm run test

# Production build
npm run build
```

### Loading in Chrome
1. Navigate to `chrome://extensions` in Google Chrome.
2. Toggle on **Developer mode** in the top right.
3. Click **Load unpacked**.
4. Select the `dist/` directory generated by `npm run build` or `npm run dev`.

## Code Quality Standards

- Strict TypeScript (`"strict": true` in `tsconfig.json`).
- Zero `any` types unless interfacing with dynamic legacy browser properties.
- Decoupled Engine: The core rule and analysis engine must remain pure TypeScript without dependencies on browser DOM APIs or React, so it can run seamlessly in headless CI test runners.
- Document any known false-positive scenarios in `docs/TESTING.md`.
